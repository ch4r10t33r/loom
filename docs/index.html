A distributed expert cache for large mixture-of-experts inference. Pool the RAM and disk of ordinary machines; serve a model none of them could hold alone.

The thesis: experts flow, not activations

A modern MoE model activates a small fraction of its weights per token — and only the routed experts change from token to token. Loom treats those experts as an immutable, content-addressed, sparsely accessed blob store. Every node runs its own full forward pass; the only thing that crosses the network is expert weight blocks — cacheable, prefetchable, digest-verified.

Because the blocks are immutable and Merkle-rooted, integrity is a free side effect: every shard is verified against the manifest digest before it touches a matmul or disk, a poisoned peer costs one rejected block, and a node that dies costs a re-fetch from a replica — never a broken pipeline.

The devnet serves Qwen3-30B-A3B (Q2_K, 6,262 content-addressed shards). Your node holds a random redundant fraction, fetches the rest from peers inside the token loop, and serves shards back. Chat UI on localhost:8555. Details: alpha guide.

Honest expectations. On slow links the win is capacity, not speed — pooling lets a swarm hold what no member can, but a partial holder on a saturated link decodes slowly. Loom is throughput-and-capacity-first serving infrastructure, not a fast single-chat engine. The numbers below say exactly where it helps and by how much.

Measured, not promised

Every design decision in loom carries a dated, append-only decision log entry with the measurement that forced it — including the negative results.

eager churn repair within one 2 s tick, plus systematic Reed–Solomon parity that rebuilds small holes — decode-then-verify, no trust in parity servers.

How it works

  • Content-addressed store — the GGUF is partitioned into expert-aligned ranges, each digest-hashed under a Merkle root; the root is the model version.
  • Committees — a bootnode assigns joiners least-covered shards, so complete coverage and redundancy hold by construction, not probability.
  • Measured fetch path — RAM → disk → peers, with holder selection weighted by each peer's measured throughput; a layer's misses are fetched in parallel.
  • Prediction — routing for every layer is predicted at layer 0 by a bolt-on head (no retraining), turning fetch stalls into overlapped prefetch.
  • Version rollout — model upgrades are majority hardforks on a new manifest root; nodes on the old version are refused, never silently mixed.
